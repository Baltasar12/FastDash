# Jolpica-F1 adapter — Phase 02B

Server-only implementation of the unchanged `F1DataProvider` v1 contract. No UI, route, database, credentials, OpenF1 integration or production fixture fallback is included.

## Usage

```ts
// Server Component or server feature/query module only.
import { jolpicaProvider } from "@/data/providers/jolpica";

const result = await jolpicaProvider.getRaceResults({ season: 2024, round: 1 });
// Narrow all four result states before reading data. Present source attribution,
// freshness, publication uncertainty and incomplete/unavailable values to users.
```

Reuse `jolpicaProvider` so logical requests share its bounded cache and in-flight deduplication. `createJolpicaProvider(options)` creates an isolated logical cache, primarily for dependency injection and tests. It accepts `fetch`, epoch-millisecond `now`, `sleep`, `random`, `timeoutMs` (1–30000; default 8000), `maxRetries` (0–2; default 2), `pageSize` (1–100; default 100) and `maxPages` (1–100; default 100). Invalid numeric configuration throws a programming/configuration error. Tests mock the local `server-only.ts` marker; Next.js enforces its `server-only` import at compilation without requiring package changes.

All seven operations resolve typed results. Requests accept only the documented integer season and, where required, round. Their validated values are snapshotted before asynchronous work. No upstream URL, selector, credential or arbitrary origin can be supplied. Expected provider failures return safe application-owned errors; raw exceptions and response bodies are not public error messages.

## Normalization and source limitations

- Canonical event/session IDs use the shared constructors. Driver, constructor and circuit IDs have explicit `jolpica` namespaces, e.g. `driver:jolpica:hamilton`. These opaque mappings are provider-scoped and stable; they are not an approved cross-provider identity join. A future mapping migration requires coordination.
- Supported-season discovery enumerates source seasons without inventing event lists, championship names or completion. Main race existence is reported by a Race object; ancillary sessions require explicit source schedule keys. Historical Sprint Shootout keeps its source label while mapping to `sprint-qualifying`. Missing ancillary sessions do not establish that no such session happened. Scheduled date-only precision stays a date; no midnight, actual start, circuit timezone, cancellation or completion is inferred.
- Finality stays `unknown`; the Ergast response has no reliable final/publication discriminator or genuine dataset update timestamp. `sourceUpdatedAt` is omitted. Retrieval is not event time. Completion of all upstream pages sets collection `completeness: complete`; this describes the returned collection, not proof that every historical entrant/metric is present or officially final. Failed/inconsistent/truncated pagination returns an error rather than fabricated partial success.
- Optional absent/null metrics remain `missing`; zero points/laps remain available zero. Nonnumeric race classification remains text with a not-applicable numeric classification. A retired driver whose source classification is numeric remains classified; retirement is separate. Unrecognized finish text is preserved with `kind: unknown`. Since 2025 Jolpica cannot distinguish detailed retirement causes reliably; no accident/mechanical cause is invented.
- Grid `0` is preserved as missing grid meaning because this API does not reliably distinguish unknown and pit-lane starts. Event results use the entry's reported car `number`; standings do not convert a driver's current `permanentNumber` into a historical seasonal number. Multiple historical entries for one driver remain distinct by constructor and entry number; duplicate composite entries and duplicate standings identities are rejected.
- Race `Time.millis` is elapsed even when displayed `Time.time` is a gap. A leading-plus display is parsed as a gap. For ordinary elapsed text, valid millis is authoritative: the official serializer can truncate a whole-second elapsed display (its `str(timedelta)[:-3]` slicing can turn an elapsed time of 10574000 ms into `2:56`). The adapter does not reject or replace valid millis because of that defective display. Without millis, ordinary display durations are parsed and validated. Empty display plus valid millis remains elapsed (a classified retiree is possible). A reported `+N Lap(s)` status can supply laps-down time. With no Time object, every recognized did-not-start spelling has not-applicable time. Durations become nonnegative numeric milliseconds without extra invented precision; average speed requires source `kph` units.
- Only supplied qualifying stage keys are retained. An explicit empty recorded stage time is missing, while an absent stage is not synthesized. `format` remains `unknown`: the official serializer also maps older formats into Q1/Q2 keys, so keys alone do not prove a modern three-stage format. Source historical coverage is not assumed from a fixed year boundary.
- **Accepted v1 limitation:** upstream driver/constructor standings can report `positionText` E (excluded), D (disqualified), or `-` (ineligible), independently of numeric ordering. Shared standings expose no classification-text field. These states normalize numeric position to `not-applicable`; their exact E/D/- distinction cannot be retained. The Product Owner explicitly accepted keeping v1 and documenting this loss; shared contracts are unchanged.
- An empty result endpoint alone does not establish a valid empty sporting classification. The adapter checks event existence, and empty season resources check supported-season discovery. Known event/season resources without published records return `not-published`; absence from discovery returns `unknown-season`/`unknown-event`. Historical unsupported coverage and unpublished records cannot always be distinguished using these source responses. `not-published` here means no published dataset was returned, not a promise it will appear later. No unsupported coverage/cancellation claim is invented, and no source-proven coverage interval is hardcoded. Only a genuinely empty global supported-season collection returns `empty`.

## Reliability, cache and quotas

The official unauthenticated limits verified above are **4 requests/second and 500/hour**, with a warning that limits may decrease. A transport-identity-shared process budget serializes network requests and enforces both rolling windows, counting retry attempts and page requests. All default factories use the same `globalThis.fetch` identity and therefore the same budget/cooldown in the same module/process. Tests may supply isolated mock transports. Wrapping transport functions or running additional processes does not provide a shared IP-wide limiter. Multi-instance/serverless production remains an explicit release blocker; [OPERATIONS.md](OPERATIONS.md) evaluates topology, restarts, shared caches, atomic quota admission and integration responsibilities. No distributed cache/locking, scheduler or persistence is claimed.

The adapter follows the v1 namespace `sector:f1:v1:jolpica:<operation>:<canonical-query>`. Validated field names are sorted; only complete logical requests are cached. Successful supported seasons have a 24-hour TTL and 7-day stale-if-error ceiling. All calendar/details use the conservative 1-hour TTL/24-hour stale ceiling; standings/results use 5 minutes/1 hour because source finality/completed-season status is unknown, even for an old year. Unavailable/empty results have a 30-second TTL and no stale fallback. Network, timeout, rate-limit and validation failures do not replace good cache entries. A subsequent valid unavailable response replaces old data; unavailable is not a usable stale dataset.

Fresh hits preserve original `retrievedAt` and `expiresAt`. Failed refreshes may return only a last successful dataset within the ceiling measured from its original expiry, with `freshness: stale` and a safe `revalidationError`; failures never extend that expiry. Availability decisions cannot rely on stale supporting season/calendar/event responses: their revalidation failure propagates as an operational failure, allowing only the outer request's own eligible stale-success fallback. They are never converted into a newly fresh unavailable response. No source check timestamp is invented because v1 has no check-time field. Values are recursively frozen. Retention is bounded to 128 logical entries and 8 MiB of estimated serialized UTF-16 data across all operations per factory; entries over 2 MiB are returned without retention. There are at most 64 in-flight logical keys per operation and 64 queued/in-progress upstream requests per transport budget. Cache eviction uses least-recently-used retention, keeping frequently accessed historical entries within the same finite TTLs. Event details can project an existing fresh calendar (or await its already requested in-flight load), preserving its original retrieval/expiry and source metadata; absent entries and stale calendars still require endpoint verification. There is no exposed manual invalidation operation; on-demand TTL refresh is authoritative.

Pagination follows validated `MRData.total`, `offset` and actual returned row counts, including nested driver/result rows rather than outer race/standings containers. Returned limits may be lower than requested. Changing totals, mismatched season/round/as-of context, duplicates, nonprogress, oversized collections or exhausted page bounds fail explicitly. Default maximum is 100 pages/10000 records with a 1 Mi-character normalized-collection bound. Individual JSON bodies are limited to 2 MiB and validated before normalization; unused enrichment fields are not copied into domain values.

Timeouts cover fetch and body consumption and abort/cancel their resources. Retryable network/timeouts/5xx failures have at most two delayed exponential/jittered retries (250/500 ms plus 0–100 ms jitter). The full retry sequence holds the shared queue turn, so queued calls do not each start an independent retry train during a failure. Invalid response/request errors are not retried. Exhausted transient failures establish a shared 5-second circuit cooldown, doubling on failed probes to a 60-second maximum; a successful HTTP JSON load resets that circuit. HTTP 429 and 503 with Retry-After return immediately and establish shared upstream cooldown. Valid numeric/date Retry-After is never shortened to 24 hours; extreme numeric values saturate at the largest representable Date and malformed values use 60 seconds. Hourly budget exhaustion returns its next permissible time. Admission rechecks both rolling windows after burst waits.

Logical operational failures are retained separately for five seconds (at most 128 keys), preserving their original `attemptedAt` and typed error. This timestamp identifies the provider operation attempt, not proof of an HTTP attempt: a different logical operation can be rejected by shared cooldown without network access. Repeated callers do not immediately retry invalid payloads or start another exhausted retry sequence. This operational suppression never overwrites a successful dataset, and stale eligibility is checked again on each call against its original ceiling. No frontend retry loop, immediate recursion or silent fallback to samples exists. Fetch's Next.js cache is explicitly disabled: a second opaque upstream cache would misstate retrieval freshness; the bounded logical server cache supplies the contract metadata and is intentionally process-local.
